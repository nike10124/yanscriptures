# 饰品机制详解（开发向）

面向维护者与整合包作者。每件饰品分两部分：**玩家可见效果**（与游戏内文案一致）
和**实现**（实现文件、挂载事件与优先级、关键常量、NBT 键）。

## 通用约定

| 约定 | 说明 |
| --- | --- |
| 佩戴判定 | `WornCache.wears(player, ClassicBook)`；每 tick 由 `ClassicBooksHandler.onPlayerTick` 刷新一次快照，不要自己遍历 Curios |
| 属性修正 | `BookAttr.set(player, attribute, uuid, amount[, operation])`，默认 `MULTIPLY_BASE`；按玩家 UUID 记账的类必须在 `SessionCleanup` 静态块 `register(...)` |
| 无条件属性 | 写在物品侧 `ClassicBookItem#getAttributeModifiers`（Curios 的「当装备在书籍栏」块），不要在 Handler 里挂 |
| 暴击 | 一律读 `l2damagetracker:crit_rate` / `crit_damage`，不用原版暴击判定 |
| 每件一文件 | 新饰品新建独立 Handler，不再往 `ClassicBooksHandler` 里塞 |
| 网络 | `NetworkHandler.CHANNEL` + `PacketDistributor.PLAYER`；HUD 类各自 `client/*Hud.java` |

### 哲学

#### 《道德经》 `dao_de_jing`

**玩家可见效果**

- 生命值降到 0 也不会死，血条看起来是空的。
- 空血时每次受击提升一级生命恢复，最高 V 级；从空血回到满血即死。30 秒结束时若生命低于 5 点（或上限的 10%，取高者），同样会死。常驻生命恢复 II。

**行为细节**

- 空血不是 0 血：用 0.5 点生命表示，否则客户端会弹死亡界面而服务端还活着，点“重生”会错位
- 空血期间 `LivingDeathEvent` 一律取消，这一击被吃掉后每秒升级生命恢复
- 回到满血即死；30 秒到点时生命低于 max(5, 上限 10%) 也会死（防“生命被固定为 1”的无敌饰品）
- 必死判定走 `hurt` → `Player#die`，被外部拦截时每刻重试，最多 60 次后放弃并补满血

**实现**

- 文件：`ClassicBooksHandler.java`（1483 行）
- 事件：LivingTickEvent（onShadowTick）；LivingHurtEvent（onLivingHurt）；LivingDeathEvent（onLivingDeath）；LivingDropsEvent（onShadowDrops，priority = HIGHEST）；LivingExperienceDropEvent（onExperienceDrop）；ItemTooltipEvent（onTooltip）；PlayerRespawnEvent（onPlayerRespawn）；Clone（onPlayerClone）
- 常量：该文件是多本书共用的分派器，各书常量按注释分段，不在此重复列出

#### 《理想国》 `republic`

**玩家可见效果**

- 攻击生物时，在它身旁投下它自己的影子；对影子造成的伤害等量转给本体。
- 影子会在 10 秒后消散。

**行为细节**

- 影子在本体朝玩家一侧 1.1 格生成，无 AI、只在原地，10 秒后消散
- 影子不可被杀死：死亡事件被取消并直接 discard，所以掉落、经验、成就、击杀统计、其它模组挂在死亡上的结算都不会发生
- 影子受到的伤害全部转给本体，转伤前后都清零本体无敌帧，因此允许“同时打本体和影子”打出两笔（同 tick 会去重）
- 同一本体不会叠出第二个影子；影子本身不计入任何账本

**实现**

### 4.1 圣典·戒律 `scripture_of_commandments`

**行为细节**

- 十诫同时生效：每条独立计数祝福/诅咒，补全后祝福换成强化档
- 不杀/不盗等判定走事件（死亡、容器开启），只对佩戴者生效
- 与《查拉图斯特拉如是说》冲突时整体失效

**判定模型**：十条诫各自两个布尔，`Curse_n`（已违逆）与 `Completed_n`（已用残卷赎清）。
某条诫处于「祝福态」当且仅当 `!Curse_n && !Completed_n`——注意 `Completed_n` 也参与判定，
所以补全过的诫既不会再触发诅咒，也不会退回未触发的初始态；
`active(player)` = 12 − 处于「已违逆且未补全」的条数，是《圣约·原典》里「十诫祝福数」的来源。

**祝福与诅咒**（数值与触发点同玩家向文档的十二诫表）：

| # | 诫条 | 祝福 | 补全后强化 | 违逆触发 | 诅咒 |
|---|---|---|---|---|---|
| 1 | 独一 | 经验 +100%，全属性 +10% | 经验 ×3，全属性 +15% | 装备任何非本模组饰品 | 攻击 -10%，每件额外 -8%（最多 -40%） |
| 2 | 无像 | 最大生命 +10% | 最大生命 +15% | 使用图腾类物品 | 图腾完全失效 |
| 3 | 圣名 | 攻击 +15% | 攻击 +20%，解封铁砧与砂轮 | 使用附魔台 / 铁砧 / 砂轮 | 攻击 -15%，附魔功能失效 |
| 4 | 安息 | 移速 +15% | 移速 +20% | 游戏日结束时静止不足 60 秒 | 缓慢 III + 挖掘疲劳 III 整天 |
| 5 | 孝道 | 村民折扣、铁傀儡保护 | 可以伤害友善生物 | 攻击友善生物 | 无法伤害友善生物，自身缓慢 III |
| 6 | 不杀 | 受伤 -20% | 受伤 -25%，清零血罪 | 击杀（首杀触发，之后叠加血罪） | 每层血罪 -7% 生命与攻击（上限 7 层） |

| 8 | 不盗 | 幸运 +2 | 幸运 +3 | 从野生的战利品容器取出物品 | 物品 30% 概率消失，抢夺无效 |
| 9 | 真言 | 攻击速度 +15% | 攻击速度 +20% | 聊天、告示牌、成书、铁砧重命名、命名牌 | 每次攻击 20% 概率落空 |

**几条容易踩的实现细节**：

- 第 1 诫「独一」：身上每有一件**非本模组**饰品就叠一层攻击惩罚（每件 -8%，封顶 -40%）；
  祝福态则是经验 +100% 与全属性 +10%。判定发生在每一次属性/经验结算前，不是在穿戴那一刻定死。
- 第 6 诫「不杀」：首杀只叠到 50% 就触发诅咒；之后每次击杀继续叠加「血罪」，
  每层 -7% 生命与攻击（上限 7 层）。血罪层数由 `BloodSin_n` 计数，补全后清零。
- 第 8 诫「不盗」：判据是**容器方块实体的 NBT 里有没有 `LootTable`**，不看是谁放的；
  自己摆的箱子若用结构方块/命令塞了战利品表，同样会被算成野生容器。
- 十诫与《查拉图斯特拉如是说》冲突：佩戴后者期间整套十诫**整体失效**，不判祝福也不判诅咒。

### 4.2 圣约·原典 `covenant_codex`

**行为细节**

- 十二权柄各自独立生效，任一满足条件即挂上对应修正或事件
- 七印是开启其余权柄的前置；`F` 键是否决飞行（会一票否决其它书的飞行许可）
- 云柱火柱（K）与《如我所书》共用一份脱困实现
- 申命之赐授予的有益效果来自原版效果表，授予时写入日志

**十二权柄**（Shift 看长页，Shift+Alt 看整屏书页）：

| 权柄 | 效果 |
|---|---|
| 万邦止戈 | 生物不主动锁定佩戴者；你亲手打过的那只获得 10 秒仇恨窗口（否则打不动依赖「锁定」判定的 Boss） |
| 不死之约 | 生命值永不低于 1；每秒回复最大生命 7% |
| 日影停住 | **Z 键**：7 秒时停，半径 64，冷却 30 秒 |
| 七碗倾倒 | **J 键**：半径 16、持续 7 秒、冷却 30 秒，每刻 × 12 种伤害类型（详见下） |
| 不可近身 | 免疫负面效果；免疫火/落/溺水/冻/雷/爆炸/岩浆；免疫禁疗；免疫直接改血；777% 反伤；无敌帧 7 秒；创造飞行 |
| 申命之赐 | 自身常驻全部原版有益效果七级；Shift+右键赐福生物、Alt+右键降灾 |
| 万军之磐石 | 777 特殊生命 + 777 点护甲/幸运/攻击/韧性等定值加成 |
| 复活在我 | 死亡事件取消 + 满血 + 清负面 |
| 万军之约 | 每击杀 +1 攻击 / +1 生命上限，上限 777 次 |
| 五饼二鱼 | 击杀后展开该生物战利品的全部条目，数量 ×2 |
| 云柱火柱 | **K 键**沿视线 8~16 格脱困（自动判定已关闭，避免误触） |
| 圣所 | 16 格内同伴受到的伤害由佩戴者承担 77% |

**高生存是怎么实现的**——四层，从外到内：

1. **完全免疫的环境伤害**：火、掉落、溺水、冰冻、雷击、爆炸、岩浆在 `LivingAttackEvent`（HIGHEST）
   直接取消，连特殊生命都不扣，也不留燃烧/冻伤痕迹。
2. **特殊生命池**：初始 777 点，存玩家持久数据 `CovenantSpecialHp`。
   其余所有伤害按 `ceil(伤害 × 0.23)` 从池里扣（这就是「受伤降低 77%」的实现方式），
   池子扣到 0 之前本体一滴血不掉；受伤 3 秒后每 20 刻回 1 点。
3. **无敌帧拉长**：每次结算后把 `invulnerableTime` 拉到 140 刻（7 秒），
   所以连续挨打不会出现「一秒吃十下」的情况。
4. **777% 反伤**：同一时刻对来源打一发 `holy_wrath`（无视护甲/抗性/无敌帧），伤害 = 本次伤害 × 7.77；
   无来源伤害（环境、效果）则反给 16 格内所有敌人。
   来源正在死亡时跳过反伤，避免在别人的死亡演出里重入。

死亡另有保险：「复活在我」直接把 `LivingDeathEvent` 取消、回满血并清负面。

**为什么不用 `heal()` / 不用 tick 巡检**：

- 回血、清负面、给效果都走事件或直接改状态，避免被《埃涅阿斯纪》那类「反转治疗」抓住。
- 所有事件体都包 `try/catch(Throwable)` 并把异常打到 stderr：
  一旦异常抛回事件总线，Forge 记录异常时会撞上 log4j 的 loader 冲突，
  把一次小错误放大成整局崩溃（`LinkageError: MessageSupplier`）。

**J 键「七碗倾倒」的伤害构成**（`JudgementController.java`）：

- 持续 7 秒（140 刻）、半径 16 格、冷却 30 秒。
- 每刻对范围内每个非玩家生物：先把它的速度清零（定身），
  然后**同一次结算里打 12 种伤害类型各一下**——`holy_wrath`、玩家攻击、魔法、凋零、溺水、
  冰冻、雷击、着火、岩浆、摔落、通用、仙人掌。
- 每一发的数值都是 `777 + 面板攻击 × 7.77`，所以「破限伤」靠的是：
  ① 12 条伤害流水线里总有一条没被限伤配置拦住；② 每条流水线本身都按魔法/环境伤害计算，
  不吃护甲与抗性；③ 训练假人只吃数字不强制扣血，真实生物走完整条。
- **兜底**：若 12 发打完目标血量几乎没动（说明每种伤害都被某处免疫/限伤吃了），
  直接把血写成 `max(0, 当前 - 计算值)`；写归零就用 `holy_wrath` 直接 `die()`。
  这条兜底是「破除限伤」的最后一道——不走任何伤害事件。

### 4.3 如我所书 `book_of_me`

**行为细节**

- 十四种光辉里每一种都由独立模块判定（增益、保命、反伤、按键），互不覆盖
- 死亡触发类效果会先把伤害清零再传送到安全位置
- 按 V 记录/回溯状态，记录内容写在玩家持久数据里
- 门径（K）与濒死传送共用 `EscapeController`，与《圣约·原典》同一套

这本书把「保命」做成四条互相兜底的战斗规则（`BookOfMeCombatHandler.java`），
只要一条生效，玩家就不会死：

**R1 负面效果免疫**：每 2 刻扫一遍身上的效果，`isBeneficial() == false` 的一律 `removeEffect`；
另外每 5 刻把血补满一次——这一条是防「绕过事件层直接 `setHealth`」的兜底。

**R2 无敌帧穿透**：攻击命中时清目标的 `invulnerableTime`，
并反射扫描目标里名字含 `invul / iframe / cooldown / hurtcool` 的整数字段与同步数据一并清零。
为什么不能只在事件里清：有模组把限制写在 `LivingEntity#hurt` 的**最开头**，早于任何 Forge 事件。

**R3 伤害免疫**：佩戴者进入 `LivingAttackEvent` / `LivingDamageEvent` 时一律取消、数值清零，
不看来源（实测某些尾杀伤害的 source 实体是空的）。另有两条全局卫生：
正在死亡的实体不再造成伤害、时停期间被冻结的实体不再造成伤害。

**R4 限伤穿透（破除限伤）**：目标是「打了不掉血」的 Boss。
攻击时把匹配到的限伤配置临时抬高到 `1.0E9`，400 毫秒无战斗后再还原：

```java
CAP_CONFIGS = {
    {"com.Polarice3.Goety.config.AttributesConfig", "ApostleDamageCap"},
    {"z1gned.goetyrevelation.config.ModConfig", "APOLLYON_HURT_LIMIT"}
}
RAISED_CAP = 1.0E9D;
CAP_HOLD_MS = 400;
```

限伤没有通用接口，只能按配置语义匹配；取不到对应配置就静默跳过（不报错、不影响正常攻击）。

**其他能力**：七印与十四种光辉（见玩家向文档）、V 键回溯、头顶铭刻的锚点等，
数值与冷却都在 `BookOfMeHandler.java` 顶部常量里。
