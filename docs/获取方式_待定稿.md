## 一、设计约束

1. **首次性**：每个条件对每个玩家只结算一次，标记写进 `player.getPersistentData()`，死亡不清、跨维度保留。
2. **后期性**：即使标「简单」的，也必须依赖后期才有资源做到。
3. **通用性**：判定只用语义阈值（最大生命值、是否 `Enemy`、原版统计量、维度、结构），不写死其他模组的实体 ID / 物品 ID。原版生物（如监守者）可直接判定。
4. **不可重复**：已获得就再也不发；丢失不补。
5. **难度分级**：★=后期随手｜★★=需要一场硬仗｜★★★=需要整套配装｜★★★★=全链毕业级。

### 技术说明 A0：「独一」的饰品豁免表

第一诫「独一」（以及示马残卷的判定）看的是**饰品栏里有没有别的神**。整合包里普遍存在
「开局必定获得、绑定后无法卸下」的诅咒饰品，以及为逆转这些诅咒而必须常驻的配套饰品，
它们与玩家信仰无关，却会让这条判定永远失败。因此有一份物品标签作为豁免表：

```
data/yanscriptures/tags/items/curio_exempt.json
```

豁免表内的饰品**既不算本模组饰品，也不算外来信仰**——完全透明，不参与任何判定。默认内容：

| 物品 | ID | 说明 |
|---|---|---|
| 七咒之戒 | `enigmaticlegacy:cursed_ring` | 开局绑定诅咒饰品 |
| 灾厄之册 | `celestial_artifacts:catastrophe_scroll` | 开局绑定诅咒饰品 |
| 七块刻蚀板 | `celestial_artifacts:{chaotic,origin,life,truth,desire,nihility,end}_etching` | 灾厄之册的七件反转道具，必须常驻佩戴 |

整合包作者往 `#yanscriptures:curio_exempt` 追加 ID 即可扩充，无需改代码或等模组更新。
`MilestoneTuning.SHEMA_REQUIRE_EXCLUSIVE_CURIOS` 默认 `true`（严格：除豁免表外不能有别家饰品），
置 `false` 会退化成「只要有一件本模组饰品就算通过」。

### 技术说明 A：「首领」怎么判定

不用生命值阈值——大整合包里普通怪的血量能涨到几百上千，「血量高 = 首领」必然大面积误判。
现在的判定在 `BossDetection.java`，分两层：

| 层级 | 规则 |
|---|---|
| 原版三首领 | 直接识别 `minecraft:ender_dragon`、`minecraft:wither`、`minecraft:warden`（它们没有标签可用，但语义上永远是首领） |
| 其它模组的首领 | 看实体类型标签：`#forge:bosses`（Forge 约定，Goety 等模组都往这里登记）、`#c:bosses`（跨加载器约定）、`#yanscriptures:bosses`（本模组兜底表，整合包可直接追加） |

```json
// data/<任意命名空间>/tags/entity_types/bosses.json
{ "replace": false, "values": ["forge:bosses", "some_mod:its_boss"] }
```

兜底表默认是空的（`data/yanscriptures/tags/entity_types/bosses.json`），因为绝大多数的首领都会自己登记
`#forge:bosses`。遇到漏标的模组，往 `#yanscriptures:bosses` 补一条即可，不用改代码。

> 判定结果影响：血声残卷的「击杀首领 ≥ 5」，以及灾厄之史诗的「单场战斗击杀 ≥ 50」里对强敌的区分。

### 技术说明 B：「一场战斗」怎么判定

没有原生「战斗」概念，我用**战斗窗口**实现，全部服务端可算：

1. 玩家**造成伤害**或**受到伤害**时，把 `combatUntil = 当前 tick + 100`（5 秒）
2. 只要 `combatUntil` 还没过，窗口视为**持续中**
3. 窗口**开启**时记下基线：`承受伤害累计`、`击杀计数`
4. 窗口**关闭**（连续 5 秒无伤害交互 / 玩家死亡 / 退出）时结算：
   - 支柱：`本窗口承受伤害 ≥ 496` 且玩家存活
   - 灾厄：`本窗口击杀 ≥ 50`
5. 结算后清空基线，下一次伤害重新开窗

这样「打一下就跑」不会累积，必须**连续 5 秒不断交火**才算同一场。5 秒的常量叫 `MilestoneTuning.COMBAT_WINDOW_TICKS = 100`。
