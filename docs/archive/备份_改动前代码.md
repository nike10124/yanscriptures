## 事故记录 001：误禁用 `mixin.env.*` 导致 runClient 崩溃（2026-10-21，已修复）

### 现象

```
MixinApplyError: Mixin [curios.mixins.json:AccessorEntity] from phase [DEFAULT]
                 in config [curios.mixins.json] FAILED during APPLY
InvalidAccessorException: No candidates were found matching f_19803_Z
                          in net/minecraft/world/entity/Entity
Process 'D:\MCModDev\jdk-17\bin\java.exe' finished with non-zero exit value 1
```

### 根因

`f_19803_Z` 是 `Entity.firstTick` 的 **SRG 名**。链路如下：

1. Curios 是第三方 mod，自带 `curios.mixins.json` 和随 jar 发布的 refmap，refmap 里存的是 **SRG 名**。
2. 本工程 `mapping_channel=official`，开发环境运行时字段名是 **Mojang 名** `firstTick`。
3. 两者对不上，Mixin 需要在加载前把 refmap 做一次 **SRG → 当前映射的反向重映射**。
4. 这一步由 `mixin.env.remapRefMap=true` + `mixin.env.refMapRemappingFile=<output.srg>` 触发。
5. 这两行被我误当作"本模组已放弃的 Mixin 遗留"注释掉了 → 重映射不发生 → Mixin 直接拿 `f_19803_Z` 去 `Entity` 里找字段 → 找不到 → 崩。

### 教训 / 规则

> **`mixin.env.*` 是开发环境的「全局开关」，服务于工作区里所有带 Mixin 的第三方依赖，不属于本模组的功能代码。**

判断方法：只要 `build.gradle` 的 `dependencies` 里存在任何**自带 Mixin** 的 mod（Curios、Create、Botania…几乎全部大型 mod），这两行就必须保留，与本模组自己是否使用 Mixin 无关。

### 结论

- 这三个混在一起的东西，只有 **一个是真问题**：

| 对象 | 作用域 | 处理 | 理由 |
|---|---|---|---|
| manifest `MixinConfigs` | 本模组发布的 jar | **必须禁用** | 声明了不存在的 `BlockDropResourcesMixin`，正式包启动即崩 |
| `examplemod.mixins.json` | 本模组的资源 | 保留，`required:false` | 无人引用时无副作用，兜底防误加载 |
| gradle `org.spongepowered.mixin` 插件 | 整个工程 | **必须保留** | 影响第三方 mod 的 Mixin 加载 |
| `mixin.env.remapRefMap` 等两行 | 整个开发环境 | **必须保留** | 同上，本次崩溃的直接原因 |

（我最初的判断把前两项和后面两项混为一类，属于审查失误。）
